# 首页推荐与关注评价流

## 已确认范围

2026-10-25，Jort要求首页演出日历下增加For You、关注的DJ、热门DJ三个Tab，并确认搜索保持顶部全局入口，城市与风格筛选只在热门DJ内。第一版复用现有DJ收藏关系作为关注，不新增订阅或推送。

首页保留现有统计、最近评价和演出日历，日历下为三Tab。推荐和关注展示可互动评价卡片；热门DJ保留现有加权排名、城市、风格/子类/标签和字母筛选。评价卡片可投赞成/反对票、展开评论、评论/回复/删除自己的评论及分享。匿名与审核反馈规则保持。

## 推荐逻辑 v1

只从已通过审核且DJ公开的最近500条评价取候选。对每条计算：

`score = (1 + 2*已关注 + 0.75*风格相近 + min(2, log1p(max(0, 有帮助票-无帮助票)))) / (2 + 距快照天数)^0.75`

风格相近指目标DJ的逗号分隔风格与收藏DJ风格存在相同项，忽略大小写与首尾空格。无关注用户按新鲜度与有帮助投票推荐。排序同分按时间和ID降序；若有其他DJ候选，不连续展示同DJ超过2条。卡片提供对应推荐原因。评价星数不参与推荐排序，不修改DJ综合分、热门DJ分数或其派生缓存。

For You是最近500条候选推荐，并非全站历史档案；关注流则对全部符合条件的已关注DJ评价按创建时间/ID倒序分页。分页沿用首屏asOf，7天后要求刷新。新投票、审核或关注变化可能使后续分页顺序变化，客户端按ID去重；不宣称冻结所有排名。客户端保存所选Tab，关注关系变化或登录账号变化刷新评价流。

## API与公开边界

新增只读GET `/api/review/feed/for-you`（可选登录）和 `/api/review/feed/following`（必须有效登录）。支持page、limit（最多50）、asOf（秒，最多回溯7天）。返回data、pagination、asOf、following_count。用户身份只从已验证JWT与数据库用户读取，忽略查询中的userId。被封禁用户403，账号失效401。

即使管理员请求status=all，也只返回approved评价与approved、未合并DJ；不返回作者账户ID、审核原因或内部推荐分。匿名作者昵称/头像强制隐藏。响应Cache-Control为private,no-store。标签批量查询，不逐条查标签。

首页复用既有评论、投票、分享接口；公开评论读取新增所属评价/DJ公开状态检查，避免已下架内容的讨论从首页继续读取。查看公开评论无需登录，写入/投票仍需登录。待审评论显示审核反馈且不增加公开评论计数。

无需数据库迁移或依赖安装。部署时先合并并上线后端接口，再上传0.3.13-beta，避免新版首页调用未上线API。
