# DJ 内容、演出、重复资料与分享码

## 添加 SET

管理员：DJ 详情页 → 管理 → 添加 SET → 填标题、粘贴视频号 `token/...` 引用内容 → 保存并展示。
从 DJ 页“管理 → 内容管理与审核”或“我的 → SET / 演出 / 重复资料管理”查看、编辑、下架。

SET 添加入口和表单仅管理员可见，后端拒绝普通用户提交SET。已发布的视频仍对所有人可见。
普通用户保留演出投稿、资料修改申请和重复资料申报；演出审核原因在“我的提交”展示。
用户分享操作统一进入“分享”面板，提供分享给朋友与DJ分享码；管理员操作统一进入“管理”菜单。

获取 token 仍由微信官方流程控制：同一操作者在 MP 后台启用权限，再从手机视频号分享菜单获取引用。
该后台权限入口的 24 小时有效期不等于已取得 token 的固定失效期。视频删除或引用失效时播放器会提示重试。
官方：https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/channels-activity.html

## 演出

每条包含名称、北京时间、城市、场地、可选地址、坐标和 HTTPS 来源链接，可关联多位 DJ。用户投稿审核，管理员直接添加。
数据库 `starts_at` 保存上海墙上时间，API 用 `UTC_TIMESTAMP() + INTERVAL 8 HOUR` 区分近期和往期，
返回固定 `YYYY-MM-DD HH:mm` 文本，前端不按手机时区再次转换。
演出日历与地图操作见下文；不包含售票、艺人认领或第三方活动抓取。

## 重复资料

用户从来源 DJ 页选择应保留的目标 DJ 并说明依据。管理员先查看两份资料，再确认合并。
同一事务中迁移全部评价（含待审/拒绝）、SET、演出，收藏去重；评价 ID 不变，保留回复、点赞、标签及评价分享。
同用户的多条评价不自动删除。源 DJ 记录保留并标记为已合并，待审资料修改申请关闭；旧 DJ 链接解析到目标。
连续合并会将旧别名指向最新目标。相关的其他未决重复申请关闭并记录原因。
合并与评分刷新共用全站评分锁，并在同一事务完成。任一步失败回滚，重复点击不会再次迁移。
新评价、收藏、内容提交及资料修改持有相应 DJ 锁或条件写入，避免合并后向来源继续写入。
生产合并必须由管理员对具体申请逐条操作；部署代码不执行任何现存 DJ 合并。没有一键撤销功能。

## DJ 分享码

公开只读入口：`GET /api/dj-content/:djId/share-code?env=release|trial`。
调用微信官方无限小程序码接口，scene 为 `d=<DJ ID>`，目标页面 `pages/dj-detail/dj-detail`。
服务端按 DJ + 环境缓存图片，限制并发生成，不向客户端返回微信 access_token。
体验版生成体验码，正式版生成正式码；旧 DJ 码通过合并映射继续进入当前主页。
保存图片由用户点击触发。微信真实生成、保存权限、扫码及版本成员限制需要部署后真机确认。

## 演出日历、原生地图与共享阵容（0.3.9-beta）

首页“演出日历”进入全站公开活动。支持城市、日期、今天、本周末筛选，以及列表／地图；均按北京时间自然日显示，00:30属于该日期。地图只展示已加载且有坐标的公开活动，列表保留无坐标活动，并显示已加载数量与总数；同一坐标的多场演出合并标记，点击后列出对应活动。

添加／编辑演出时“在地图搜索场地”使用微信原生 `wx.chooseLocation`，不使用第三方插件、不需要腾讯位置服务Key。成功后填写场地、地址及GCJ-02坐标，清空城市并要求用户确认城市；原生接口没有稳定的独立城市返回值，不从地址猜测。取消选点不清空旧表单；接口不可用时可手动输入。修改场地名／地址会清除旧坐标，避免地图误标。

小程序后台仍需开通 chooseLocation 接口，并在用户隐私保护指引中声明位置用途。代码已在app.json声明requiredPrivateInfos与定位用途，并同步应用内隐私说明。CLI编译通过不代表后台权限或真机选点已通过。未开通时保留手动录入。原生map显示已存场地坐标，不获取浏览者当前定位；活动详情可调用wx.openLocation查看路线。

一场演出只创建一个dj_events记录，dj_event_djs关联最多30位现有、已通过的DJ，必须包含录入入口DJ。普通用户投稿整场活动待审，管理员通过后在所有阵容DJ页与日历公开；管理员可编辑阵容并整体下架。重复DJ合并时迁移、去重关联关系。现存活动ID不变，迁移017为旧活动补齐主DJ关联。重复活动不会根据标题自动合并。

新增公开接口（均在/api/dj-content下）：
- GET /events?from=YYYY-MM-DD&to=YYYY-MM-DD&city=&page=1&limit=50：日期范围最多93天，每页最多50条，返回阵容与地址/坐标；默认今天。
- GET /events/cities：仅公开活动的城市。
- GET /events/:id：公开活动详情；待审/拒绝活动返回404。
原有创建/更新events接口新增address、latitude、longitude、dj_ids。无坐标使用null；坐标成对且在合法范围。

迁移017只新增可空字段、关系表和索引，可重复执行；无评分或业务状态更新。先部署后端及迁移，再上传小程序验收。


## 0.3.10 界面调整

DJ 分享码入口与分享面板已移除；DJ头部操作区恢复原生直接分享。已生成分享码的scene解析仍保留，兼容已分享的链接。
DJ详情“最近演出”最多3条，优先将到来的演出、剩余位置补最近往期；无记录显示暂无演出信息。总数超过3时“查看全部”进入仅该DJ的独立演出页，近期/往期横向切换、按需分页；详情页不再追加长列表。首页演出日历入口位于最近评价下方，白底黑字与浅灰边框。
权限核对：管理仅登录管理员可见，添加SET/演出、直接编辑资料、审核编辑上下架及确认合并均管理员服务端校验；标记重复是申报，普通登录用户也可在投稿里使用。普通投稿包含演出/资料修改申请/重复申报，需管理员处理；访客可读公开内容及分享。未登录时即便残留缓存admin角色，也不显示管理。
本批仅小程序改动，复用现有后端接口，无新增迁移。
