# DJ 内容、演出、重复资料与分享码

## 添加 SET

管理员：DJ 详情页 → 管理 → 添加 SET → 填标题、粘贴视频号 `token/...` 引用内容 → 保存并展示。
从 DJ 页“管理 → 内容管理与审核”或“我的 → SET / 演出 / 重复资料管理”查看、编辑、下架。

SET 添加入口和表单仅管理员可见，后端拒绝普通用户提交SET。已发布的视频仍对所有人可见。
普通用户保留演出投稿、资料修改申请和重复资料申报；演出审核原因在“我的提交”展示。
用户分享操作统一进入“分享”面板，提供分享给朋友与DJ分享码；管理员操作统一进入“管理”菜单。

获取 token 仍由微信官方流程控制：同一操作者在 MP 后台启用权限，再从手机视频号分享菜单获取引用。
该后台权限入口的 24 小时有效期不等于已取得 token 的固定失效期。视频删除或引用失效时播放器会提示重试。
官方：https://developers.weixin.qq.com/miniprogram/dev/framework/open-ability/channels-activity.html

## 演出

每条包含名称、北京时间、城市、场地、可选 HTTPS 来源链接。用户投稿审核，管理员直接添加。
数据库 `starts_at` 保存上海墙上时间，API 用 `UTC_TIMESTAMP() + INTERVAL 8 HOUR` 区分近期和往期，
返回固定 `YYYY-MM-DD HH:mm` 文本，前端不按手机时区再次转换。
没有售票、地图、艺人认领或第三方活动抓取。

## 重复资料

用户从来源 DJ 页选择应保留的目标 DJ 并说明依据。管理员先查看两份资料，再确认合并。
同一事务中迁移全部评价（含待审/拒绝）、SET、演出，收藏去重；评价 ID 不变，保留回复、点赞、标签及评价分享。
同用户的多条评价不自动删除。源 DJ 记录保留并标记为已合并，待审资料修改申请关闭；旧 DJ 链接解析到目标。
连续合并会将旧别名指向最新目标。相关的其他未决重复申请关闭并记录原因。
合并与评分刷新共用全站评分锁，并在同一事务完成。任一步失败回滚，重复点击不会再次迁移。
新评价、收藏、内容提交及资料修改持有相应 DJ 锁或条件写入，避免合并后向来源继续写入。
生产合并必须由管理员对具体申请逐条操作；部署代码不执行任何现存 DJ 合并。没有一键撤销功能。

## DJ 分享码

公开只读入口：`GET /api/dj-content/:djId/share-code?env=release|trial`。
调用微信官方无限小程序码接口，scene 为 `d=<DJ ID>`，目标页面 `pages/dj-detail/dj-detail`。
服务端按 DJ + 环境缓存图片，限制并发生成，不向客户端返回微信 access_token。
体验版生成体验码，正式版生成正式码；旧 DJ 码通过合并映射继续进入当前主页。
保存图片由用户点击触发。微信真实生成、保存权限、扫码及版本成员限制需要部署后真机确认。

## 发布与验证

当前版本 0.3.8-beta（0.3.7已部署迁移016；0.3.8不新增迁移）。先通过原 `scripts/sync-to-rds.sh` 应用 `016_dj_content_tools.sql`，再重启后端。
迁移新增 `djs.merged_into_id` 及 `dj_sets`、`dj_events`、`dj_duplicate_reports`；仅导入已由 Jort 确认的 DJ9 视频。
迁移可重复执行，不迁移、合并或删除现有 DJ / 评价。
新小程序依赖这些接口，不在后端尚未部署时上传并声称可验收。先确认本批上线范围，后端上线再上传并真机验证。
旧小程序继续可用，原有 DJ 与评价 ID 链接保留。

自动验证：

- `node --test tests/*.test.cjs`
- `python3 tests/run-dj-content-mysql.py`（先安装后端依赖，或用 `--node-modules PATH` 指向已安装的同版本依赖）
- 微信 CLI preview 编译。

MySQL 脚本仅创建并清理本机一次性 Docker 容器，使用随机回环端口和虚构数据，不连接生产或建立测试环境服务。
集成测试覆盖权限、归属、审核、公开字段、北京时间、原子合并、回滚、并发发评价、旧链接及评分核对。

生产验收：管理员添加/编辑/下架 SET，普通用户不得提交SET；演出投稿与反馈；近期/往期演出与来源；分享码生成、保存、扫码；
重复资料流程在确认真实重复条目前只验证申报和审核展示，不为测试而合并真实资料。部署后再次运行只读评分审计。
